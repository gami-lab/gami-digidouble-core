# Add the Lint Guardrail, Harden, and Close the EPIC

# Context

Prompts `01`–`05` cleaned the codebase. Without a guardrail, agents will add narration comments and
unexplained suppressions again within a few EPICs. This prompt adds lint checks that run in
`pnpm lint` and the existing `lint-staged` pre-commit hook, runs the full gate, and closes the EPIC.

# Scope

In scope:

- ESLint `linterOptions.reportUnusedDisableDirectives: 'error'`.
- A small local ESLint rule (no new dependency) in the repo, e.g. `eslint-rules/no-agent-comments`,
  that reports:
  - change-narrating comments (`Updated …`, `Added …`, `Changed …`, `Fixed …`, `Now …`,
    `Refactored …` at comment start)
  - AI attribution (`Added by AI`, `Generated by`, `Claude`, `Copilot`, `Codex`)
  - epic/prompt references (`EPIC-`, `epic 4.2`, `TODO(EPIC`)
  - `eslint-disable*` directives without a `-- reason`
- Built-in `no-warning-comments` for `TODO`, `FIXME`, `HACK`, `XXX`.
- Unit tests for the local rule using ESLint's `RuleTester`: flagged and allowed examples,
  including JSDoc, "why" comments, and directives with reasons.
- Full repository gate and final searches.

Out of scope: auto-fixing or stripping comments. The rule reports; a human or agent decides
whether to delete or rewrite.

# Implementation Guidance

- Keep the rule small: one regex list for comment starts and attribution, applied to
  `sourceCode.getAllComments()`. Avoid fuzzy heuristics that flag legitimate comments; tune with
  the RuleTester cases, then run it on the whole repo.
- Register the rule in `eslint.config.mjs` as a local plugin. Note that `**/*.mjs` is currently
  ignored by lint; decide whether the rule file is linted or excluded, and keep it consistent.
- Check the rule also applies to `.vue` files if the apps lint them.
- Confirm `lint-staged` runs ESLint on staged `*.ts` files so the hook blocks a flagged comment;
  test it by staging a file with a flagged comment and checking the commit is refused (then discard
  that file).
- Final searches over `apps/ packages/ tools/`: `TODO|FIXME|HACK|legacy|workaround`,
  `eslint-disable` without `--`, `as unknown as` and `as any` outside tests. Every remaining hit
  must be in the inventory with a reason.

# Constraints

- No new third-party dependency; ESLint's rule API is enough.
- Do not loosen existing lint rules or thresholds.
- Lint must pass on the cleaned codebase with the new rule as `error`.

# Deliverables

- Local `no-agent-comments` rule with RuleTester tests, enabled as `error`.
- `reportUnusedDisableDirectives` and `no-warning-comments` enabled.
- Green `pnpm lint`, `pnpm typecheck`, `pnpm build`, `pnpm test`.
- Inventory marked complete with final counts.

# Mandatory Pre-Implementation Check

1. Identify any contracts still flagged as follow-ups in the inventory.
2. Re-search for duplicated type definitions introduced during prompts `02`–`05`.
3. Confirm the canonical owner of every contract touched in this EPIC.
4. Confirm shared types are reused rather than copied.
5. Record any remaining duplication as an EPIC follow-up instead of leaving it silent.

# Mandatory Final Step — Documentation Update

Update `docs/PROJECT_STATUS.md` and mark EPIC 11.2 done in `docs/EPICS.md` (move it to Shipped with a
short summary). Update `AGENTS.md` to point to the lint rule, `docs/TEST_STRATEGY.md` for the
rule's tests, and `docs/TECH_STACK.md` if the lint setup section describes rules. If any doc needs
no change, verify and state that it is accurate. Run formatting and `git diff --check`, review
`git status`, and commit as `chore(lint): enforce comment policy (epic 11.2)`.

# Acceptance Criteria

- [ ] A narration comment, AI attribution, epic reference, `TODO`, or disable without a reason fails
      `pnpm lint` and the pre-commit hook.
- [ ] RuleTester covers flagged and allowed cases.
- [ ] Unused disable directives are errors.
- [ ] Full gate passes on the cleaned codebase.
- [ ] EPIC 11.2 marked done in `docs/EPICS.md` and `docs/PROJECT_STATUS.md`.
